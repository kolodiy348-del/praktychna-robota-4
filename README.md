# Практична робота №4 — тестування та оптимізація вебзастосунку

## Проєкт
Адаптивне портфоліо з HTML5, CSS3, JavaScript, Python Flask і SQLite. Форма надсилає дані асинхронно; адміністратор може переглядати та видаляти повідомлення.

## Локальний запуск
1. Встановіть Python 3.12+.
2. У каталозі проєкту виконайте `python -m pip install -r requirements.txt`.
3. У Windows CMD задайте `set "ADMIN_PASSWORD=ваш_складний_пароль"` та `set "SECRET_KEY=довгий_випадковий_секрет"` (не публікуйте значення).
4. Виконайте `python server.py` та відкрийте http://127.0.0.1:5000.
5. Панель адміністратора: http://127.0.0.1:5000/messages.

## Автоматичні тести
`python -m unittest discover -s tests -v`

Тести використовують тимчасову SQLite БД, не змінюючи робочі повідомлення. GitHub Actions запускає їх після push і pull request.

## Перевірка адаптивності та Lighthouse
У Chrome DevTools перевірте 375, 768 та 1440 px. Lighthouse: DevTools → Lighthouse → Analyze page load; збережіть скриншот результату. Перевірте вкладку Console на помилки JS. Фактичні показники Lighthouse потрібно виміряти локально, вони не наведені як вигадані результати.

## Git та GitHub
Створіть порожній репозиторій на GitHub, потім у каталозі проєкту:
```
git init
git add .
git commit -m "Initial website and backend"
```
Для вимоги трьох змістовних комітів вносьте та комітьте **реальні окремі зміни** (наприклад, виправлення інтерфейсу, тести, документація). Не створюйте фіктивні коміти. Після створення віддаленого репозиторію виконайте команди, які покаже GitHub для `git remote add origin` та `git push`.

## Безпека
Не додавайте в GitHub паролі, `messages.db`, журнали або секретні ключі. Flask development server призначений лише для локальної роботи. Для публічного HTTPS потрібні окремі налаштування хостингу та захист від зловживань.
